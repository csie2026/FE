# 설정·회원탈퇴 FE — Issue #24 정책 후속 작업

메뉴와 헤더의 계정 설정을 설정으로 변경했다. 내부 accountSettings 화면 식별자는 기존 탐색 이력과 호환하도록 유지한다. 설정 화면에서 삭제 대상·복구 불가·외부 소셜 계정 유지·로그/백업 정책 미정 안내를 읽고 삭제 범위와 복구 불가 안내에 동의하는 체크 후 “회원 탈퇴” 버튼으로 요청한다. 문구 직접 입력은 요구하지 않는다. 구체적인 환경설정 항목은 요구가 확정되지 않아 추가하지 않았다.

공통 API 클라이언트의 세션/CSRF 처리를 사용하고, CSRF 준비 뒤 현재 회원을 다시 확인한다. BE에 expectedUserId를 전달해 다른 계정으로 바뀐 경우 삭제하지 않는다. 204만 성공으로 처리한다. 요청 실패·응답 유실·시간 초과는 완료로 단정하지 않으며 연속 클릭과 처리 중 화면 이동을 차단한다.

성공 후 로그인 화면으로 이동하고 해당 회원의 찜·임시 GPS 기록을 localStorage와 sessionStorage에서 삭제한다. 다른 회원 키는 건드리지 않는다. 메모리의 회원·일지 입력 상태도 비운다. 진행 중인 GPS checkpoint/찜 쓰기가 탈퇴 회원 데이터를 다시 저장하지 않게 한다. 활성 탭에는 BroadcastChannel로 전달하고, 다른 기기는 서버의 account_unavailable 응답을 확인한 뒤 해당 키를 정리한다. 일반 세션 만료를 탈퇴로 오인해 데이터를 삭제하지 않는다.

저장소 접근이 거절되면 서버 탈퇴 성공과 브라우저 정리 실패를 구분하고 정리 재시도 버튼을 제공한다. 오프라인/닫힌 기기의 저장소를 원격 삭제할 수는 없다. 서버 응답을 잃은 뒤 세션 식별도 없어지면 브라우저 정리가 자동 완료됐다고 보장하지 않는다. 미확인 삭제는 로그인 상태를 확인해야 한다.

검증: FE 자동 테스트 161개 통과, build 성공, lint 성공. 모의 API 기반 390px 브라우저 시나리오 8개 통과(확인/취소, 실패, 성공/타회원 보존/다른 탭, 뒤로가기, 저장소 거절/재시도, 계정 전환, 일반 만료, 응답 유실). 이는 실제 OAuth/운영 DB/실기기 E2E 검증과 구분한다.

새 API는 DELETE /api/users/me이며 별도 개인정보 저장 API/환경설정 스키마는 추가하지 않았다. PR 전에 별도 BE Java 21 테스트 결과와 실제 연동 결과를 기록해야 한다. 정책 검토 상태는 BE docs/account-withdrawal.md를 참조한다.

최종 확인 UI 정책: 동의 체크 전에는 최종 버튼을 비활성화하고, 체크 해제/취소 시 동의를 해제한다. 텍스트 입력란은 제거했다. 기존 BE의 confirmation 필드는 동의 후 명시적인 최종 클릭 시 기존 값으로 전달한다. 본인 ID/CSRF/계정 전환 검증을 유지하며 BE API나 DB 변경은 없다.
